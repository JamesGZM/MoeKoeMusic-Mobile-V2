# 独立用户主页纯 UI 与 Feature 所有权审计

状态：Approved for implementation。审计日期：2026-08-08。

## 范围与完成语义

本切片把已确认的 [`10-user-profile.png`](../design/mockups/10-user-profile.png) 落为 Android 原生独立用户主页，并从登录后的“我的”资料卡进入、返回原来源。可观察的完成语义是：标准 Toolbar、资料 Hero、关系统计、编辑资料、听歌概览、创建歌单和应用级 MiniPlayer 避让完整可见；页面滚动、系统返回和大字体状态可自动验证。

本切片只交付 UI 状态与明确事件边界。关注/粉丝/好友、等级、听歌时长、乐龄、签名、编辑资料、分享、公开歌单与更多操作的协议和行为均为后续纵向切片；不得把设计示例计数、歌单或账号字段写入 Repository、数据库或领域模型，也不得据此声明功能已接入。

## 既有能力与差距

- `:feature:my` 已消费真实 `UserProfileRepository`，拥有匿名、加载、资料成功、VIP 降级和退出状态；当前资料卡点击主要打开账号菜单，尚无独立用户主页目的地。
- `UserProfile` 目前只稳定提供用户 ID、昵称、头像和可选 VIP 摘要，不提供 `10` 稿中的社交统计、等级、签名、听歌概览和公开歌单。
- `MoeStandardTopBar`、音乐行、徽标、主题、MiniPlayer 和应用壳已经稳定，不需要为本页面复制公共组件。
- `feature/my` 已有与确认稿相符的本地头像、ACG 与夜间歌单图片，可作为截图 fixture；生产数据接入时改为真实 URL，不把 fixture 下沉到数据层。

## 决策

### 模块所有权

建立独立 `:feature:profile`，而不是把页面塞入 `:feature:my`。用户主页未来会从“我的”、关注/粉丝列表、搜索和内容作者入口复用；独立 Feature 避免这些来源模块互相依赖。

- `:feature:profile` 拥有类型化目的地、不可变 UI Model、Screen、截图和页面事件。
- `:feature:my` 只新增 `onProfile` 事件，不依赖 `:feature:profile`。
- `:app` 连接 My → Profile 与返回栈，并继续决定一级底栏和 MiniPlayer 的显示规则。
- 首个纯 UI 切片不新增 Repository、ViewModel、Hilt Module、数据库表、网络调用或第三方依赖。

### 运行态边界

首个目的地允许渲染明确登记的设计预览状态，用来完成已确认页面的视觉和导航交付；该状态只存在于 `:feature:profile` UI 层，不进入协议、领域、缓存或持久化。真实资料接入时必须用独立提交替换组合根中的预览输入，并为缺失字段使用明确的不可用/空状态，不得继续显示示例计数。

匿名用户仍由“我的”现有统一登录门禁拦截，不会进入用户主页，也不会新增第二个登录目的地。

## 状态与交互矩阵

| 状态 | 页面表达 | 交互边界 |
| --- | --- | --- |
| 正常内容 | 完整资料 Hero、三项关系统计、听歌概览、创建歌单 | 返回可用；分享、更多、编辑、统计、查看全部、歌单与行菜单只上抛事件 |

| 错误 | 标准 Toolbar 保留，正文显示错误与重试 | 返回与重试可用 |
| 离线 | 与错误分离的离线文案和重试 | 返回与重试可用 |
| `1.5×` / `2.0×` | Hero 和统计按可用宽度重排，正文单一纵向滚动 | 不横向裁切，不嵌套纵向滚动 |

## 安全、隐私与失败边界

- 截图只使用确认稿示例和仓库本地图片；不记录真实用户 ID、头像 URL、签名、关系数量或服务载荷。
- UI 不直连网络、DataStore、数据库或播放 Service。
- 分享、编辑资料和关系入口不使用 Toast 或假成功反馈掩盖未接入行为。
- 头像失败、长昵称、长签名和缺失 VIP 必须有布局回退；真实字段接入前由截图状态证明容器可承载，不虚构默认业务值。
