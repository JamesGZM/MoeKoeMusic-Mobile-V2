# UI 设计基准

状态：第一版核心视觉、登录方向和通用组件体系已批准。页面结构确认日期：2026-08-04；Design System 确认日期：2026-08-05。本文与指定设计稿共同作为 Compose UI 的实现基准：确认稿决定页面视觉几何，页面适配契约决定运行时映射，[`DESIGN_SYSTEM.md`](DESIGN_SYSTEM.md) 决定颜色语义、交互状态、无障碍下限和共享组件行为。

## 设计目标

- 延续 PC 端简洁、高颜值、弱社交的品牌性格。
- 第一版承载 PC 端主要功能，但重新设计移动端信息架构。
- Material 3 作为交互和组件基础，不使用默认模板化外观。
- 正式页面编码前先锁定对应设计图和可复用组件；设计确认后同步文档，最后修正 Compose 实现。
- 缺少页面或状态设计时先在既有 MoeKoe Air 语言内生成静态候选图，用户确认后才允许制作必要的交互原型；原型不能先于设计图或替代设计确认。
- 播放器和歌词成为最强产品识别点。
- 保持长列表信息密度，避免所有内容卡片化。

## 已确认视觉方向

- 内容页面采用明亮、清透、品牌化的 Material 3，不使用默认示例配色。
- 基础色为暖白表面与天空蓝主色，淡蓝容器承担层级，淡紫和薄荷绿仅用于辅助强调。
- 内容页保持较高信息密度，歌曲使用紧凑 `ListItem`，不把普通列表项全部卡片化。
- 播放页采用深色沉浸模式，参考 Kreate 的大封面、封面驱动背景和歌词氛围。
- 播放页不照搬 Kreate 的 Logo、系统栏、多层底栏和高密度操作按钮。
- 歌曲标题与主要操作按约 `16sp` 设计，说明与歌手信息原则上不低于 `14sp`；仅徽标、时长等辅助信息可使用 `12sp`。
- 交互目标不小于 `48dp`，支持系统字体缩放。设计稿像素作为设计坐标而非 Android 原始像素；页面在当前窗口中按统一比例映射，禁止组件独立改尺寸。

## 信息架构

底部三个一级入口：

1. 首页。
2. 发现。
3. 我的。

搜索不是一级 Tab。用户从首页搜索框进入独立子页面，子页面提供返回操作，不显示底部一级导航。

内容归属：

- 排行榜、新歌、新专辑、分类歌单归入发现。
- 发现页取消重复的页面标题栏，内容分类 Tab 直接置于页面顶部。
- 收藏、用户歌单、云盘、本地音乐和历史归入“我的”。
- 登录状态和用户资料通过“我的”页顶部个人卡片呈现，不再叠加页面标题和独立头像。
- 点击个人卡片进入独立用户主页；用户主页是带返回操作的子页面，不显示一级底部导航。
- 设置入口放在个人卡片右上角，并保持不小于 `48dp` 的触控区域。
- 个人卡片必须保留 PC 端的两个关键操作：“签到”和“领取 VIP”。两者使用明确的 Material 3 按钮，当前 VIP 徽标只表达权益状态。
- “签到 / 领取 VIP”需要覆盖未登录、请求中、领取成功、今日已领取、接口不可用和账号风控状态；成功后刷新 VIP 状态。
- “我的”不使用“创建的 / 收藏的”Tab。收藏歌单、收藏专辑、关注歌手和关注好友组成固定的“收藏与关注”入口组，创建歌单则作为独立内容区展示。
- “最近播放”只保留快捷入口，不在同一首屏重复渲染横向内容区。
- MiniPlayer 常驻在底部导航上方。

用户主页承载头像、昵称、等级、VIP 状态、签名、关注/粉丝/好友数量、听歌时长、注册时长和公开创建歌单。“签到 / 领取 VIP”、云盘、本地音乐与设置仍属于“我的”，不复制到用户主页。

宽屏时底部导航转换为 Navigation Rail，详情页面可采用列表与内容双栏结构。

## 登录视觉

- 登录主状态采用 [`13-login-phone-immersive.png`](design/mockups/13-login-phone-immersive.png) 的沉浸式方向。
- 登录的基准画布、统一缩放、系统边界、宽屏派生和视觉对比门禁统一遵循 [`LOGIN_LAYOUT_SPEC.md`](design/LOGIN_LAYOUT_SPEC.md)。该契约与确认稿共同高于现有 Compose 实现和历史截图。
- 登录补充状态必须直接以 `13-login-phone-immersive.png` 的完整画布作为像素基座，只替换登录卡片内规格允许变化的状态内容；Hero、卡片外框、分段控件及固定间距不得重新生成。隔离安全验证 Activity 和“我的”页账号切换 Bottom Sheet 分别使用各自明确记录的页面基座，不套用登录卡片。
- 插画绘制到状态栏后方，不设置独立白色 App Bar，也不重复显示“登录”标题。
- 返回按钮位于系统安全区内，图形复用 Design System 的无横杆圆端 `MoeNavigateBackIcon`，并使用登录页自己的 `48dp` 触控区域、设计锚点和按登录画布统一缩放的半透明圆形 Surface；不得复制页面命名资源，也不得用形态不符的 Material 返回图标近似。
- 验证码、密码和扫码使用同一表单 Surface 内的分段切换，不拆成三套无关视觉语言。
- 密码提交触发额外风险验证时，保留密码表单、当前账号输入和页面层级，以遮罩上的安全验证 Dialog 说明原因并提供“开始验证 / 取消”操作；Dialog 必须相对完整可用视口居中，取消 Tonal Button 与右侧 Filled Button 同高、同一基线，不得相对底部表单居中，也不得用内联卡片或下沉面板替换密码表单主体。只有用户确认开始后，才进入隔离的腾讯验证容器或短信二次验证步骤，取消与返回必须回到原密码草稿。
- 多账号选择只在接口确实返回多个账号后显示，不在默认登录状态常驻。
- 普通操作图标优先复用 Compose Material Icons，不为已有标准语义重复制作 SVG。

## 播放器层级

### MiniPlayer

- 封面、歌曲名、歌手。
- 播放/暂停与下一首。
- 简洁进度提示。
- 点击展开全屏播放器。
- 作为 `surfaceContainerHigh` 色调表面与底部导航连续排列，不使用悬浮玻璃胶囊。

### 全屏播放器

- 大封面和封面驱动背景。
- 标题、歌手、收藏、音质和更多操作。
- 进度、播放模式、上一首、播放暂停和下一首。
- 封面与歌词间的清晰切换。
- 默认进入封面模式；封面与歌词使用横向分页切换，并提供明确页码指示。
- 支持纵向退出和系统预测返回。

### 队列

- 手机使用 `ModalBottomSheet`，宽屏可转换为 Supporting Pane。
- 当前歌曲、下一首、来源信息。
- 拖拽排序、移除和下一首播放。
- 播放模式和清空操作。

## 视觉原则

- 主题支持浅色、深色和纯黑。
- 默认品牌主题具有稳定主色，不完全依赖系统动态色。
- 播放器的布局和视觉关系由确认稿固定，实际色板必须由当前歌曲封面派生；封面页与歌词页共享同一个经过亮度、饱和度和对比度修正的语义色板，设计稿示例色不得硬编码。
- 切歌、封面缺失或取色失败时使用 MoeKoe 深色静态渐变；上一首异步取色结果不得污染下一首。详细门禁见 [`reference-audits/13-player-artwork-palette.md`](reference-audits/13-player-artwork-palette.md)。
- 大面积模糊和玻璃效果谨慎使用，低端设备提供静态渐变回退。
- 列表以排版、留白和细分隔建立层级，不依赖厚重阴影。
- 圆角、间距和动画来自统一 token。
- 颜色、字体、间距、圆角、图标与触控规则统一遵循 [`DESIGN_SYSTEM.md`](DESIGN_SYSTEM.md)，业务页面不得从设计图取样后自行定义近似值。
- 歌词高亮应兼顾逐字进度、翻译/音译和可读性。

## Dialog 与即时反馈

- Dialog、`MoeSnackbar`、`MoeToast` 和系统 Toast 统一遵循 [`UI_COMPONENTS.md`](UI_COMPONENTS.md)。
- 可操作或可恢复反馈使用品牌化 `MoeSnackbar`；应用前台的低优先级无操作结果使用 `MoeToast`；系统 Toast 只作为无法使用 Compose Host 时的系统样式回退。
- 危险操作、文本输入和必须确认的流程使用 Dialog；持续状态使用页面内组件，不用瞬时反馈替代。
- `MoeSnackbar` 与 `MoeToast` 始终位于 MiniPlayer、底部导航和 IME 上方，不能遮挡播放控制。

## 必须设计的状态

- 匿名设备注册由实际发起请求的页面承接加载与失败，不建立独立启动页。
- 未登录、已登录和会话失效。
- 加载、空数据、部分加载失败和完全失败。
- 无网络、弱网和缓存内容。
- 无版权、VIP 限制和播放地址失效。
- 无歌词、歌词加载失败和歌词时间偏移。
- 本地权限未授予和文件失效。
- 横屏、平板、大字体和深色模式。

## 本地音乐 UI

阶段 3 已完成本地音乐列表、设备扫描与多选、App 内导入、外部打开进度、空状态、搜索、排序、MiniPlayer、队列和删除确认的纵向闭环。权限拒绝、空间不足、损坏/不支持、重复内容和批量结果使用同一领域状态与反馈语言，不建立独立主题。本地音乐内容已接入统一歌曲行，空状态、内容状态和 `1.5×` 字体导入状态已有稳定截图基准；其余异常态视觉强化继续归入阶段 5A，不再阻塞阶段 3 的功能验收结论。

外部“打开方式”页面必须准确表达复制进度；只有导入成功后进入播放。持续进度使用页面内组件，阶段结果使用 `MoeSnackbar`，不得使用 Toast 连续刷新。

## 后续仍需设计与验证

- 当前仓库已有设计图均为已确认实现基线，无需重复确认；只有现有图片没有覆盖的新页面或关键状态才先补静态图并等待确认。
- 启动不需要额外设计稿：Android 系统 Splash 后直接进入应用壳。设备注册、会话失效、网络和缓存状态只在实际消费数据的页面内设计与验证。
- 使用 [`login-flow`](design/prototypes/login-flow/README.md) 原型继续验证轮询、返回与 WebView 生命周期；真实协议时序和 Activity 重建仍需 Android 测试确认。
- 现有图片未覆盖的加载、空数据、错误、离线、无版权和 VIP 限制状态。
- 深色内容页、纯黑主题和高对比主题。
- 平板、横屏和折叠屏双栏结构。
- 大字体、TalkBack、触控目标和颜色对比度。
- 使用 [`player-flow`](design/prototypes/player-flow/README.md) 已锁定的交互关系完成播放器 Compose 转场、封面/歌词分页、队列展开、预测返回和性能降级动效验证。
- 本地音乐列表、导入、扫描、批量结果与异常状态。
