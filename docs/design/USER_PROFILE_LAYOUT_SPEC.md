# 独立用户主页设计复刻与屏幕适配契约

状态：Accepted。确认日期：2026-08-08。适用范围：独立用户主页正常、加载、空、错误、离线与大字体状态。

本文把已确认的 [`10-user-profile.png`](mockups/10-user-profile.png) 转换为可执行的 Android UI 契约。首个切片先交付页面视觉、导航和事件端口，不等待用户主页业务接口，也不以设计示例数据冒充真实结果。

## 权威来源

1. `10-user-profile.png` 决定信息层级、坐标、尺寸比例、间距、圆角、头像/封面裁切和首屏密度。
2. [`../DESIGN_SYSTEM.md`](../DESIGN_SYSTEM.md)、`15-toolbar-navigation.png` 与 `17-music-content-components.png` 决定主题语义、标准 Toolbar、最小触控区和音乐内容组件行为。
3. 当单页稿与已确认公共规范冲突时，公共规范优先；本页本身就是标准 Toolbar 的坐标母版。

## 基准画布与应用壳

- 原稿 `853 × 1844px` 按宽度等比映射到 `390dp` 设计视口，单一比例约为 `0.4572dp/px`。
- canonical 结构截图固定为 `390 × 843dp`；原有 `390 × 764dp` Light 截图仅作为短视口滚动回归，不作为设计 crop 或锚点真值。
- Android 负责状态栏、导航栏与安全区；应用不绘制时间、信号、Wi-Fi 或电池图形。
- 页面使用 `MoeStandardTopBar`：`64dp` 内容高度、页面中心标题、左侧共享 Chevron，右侧分享与更多各自占至少 `48dp` 触控区。
- 用户主页是子页面：一级 NavigationBar 隐藏，应用级 MiniPlayer 在存在当前歌曲时保留。页面正文只消费 App 下发的底部安全留白，不自行复制 MiniPlayer。
- 内容使用一个 `LazyColumn`；标准手机宽度不嵌套纵向滚动，不用固定整页高度压缩下方内容。

## 页面结构

### 资料 Hero

- 页面水平边距 `16dp`，Hero 占满可用宽度，圆角 `24dp`，使用低对比 Primary Container 渐变和细描边；不得用纯白无边界区域替代。
- Hero 紧接标准 Toolbar，不额外增加顶部 Spacer；由 Toolbar 自身高度建立标题与内容的垂直节奏。
- 标准字体下头像约 `84dp`，圆形裁切并有轻量描边；昵称、VIP、等级和签名形成右侧信息组。昵称优先保留，徽标允许换行或收紧间距。
- 关注、粉丝、好友是三等分统计，中间使用低对比分隔线；数字为 Primary，说明为 On Surface Variant。整组是可点击语义，不用三个视觉卡片。
- 编辑资料的语义触控区为 `48dp` 高；设计稿中的可见描边 Surface 固定为 `38dp` 高、`9dp` 圆角，贴触控区顶部放置并在底部保留约 `10dp` 透明点击余量。图标为 `20dp`，文字使用 `titleSmall`（`16sp / 24sp`、SemiBold）。不得再把最小触控高度直接当成可见按钮高度。

### 听歌概览

- 区标题与 Hero 之间保持确认稿约 `20–24dp` 的视觉节奏；“听歌概览”与“创建的歌单”统一使用 `titleSmall`（`16sp / 24sp`、SemiBold），避免把分区标题放大成页面级标题。
- 概览 Surface 水平边距 `16dp`、圆角 `20dp`、低对比描边，三列展示等级、听歌时长和乐龄；单位使用较小字号但与主值同一基线语义。
- 大字体下改为纵向或 `2 + 1` 重排，不能缩小文字、挤出边界或隐藏任一指标。

### 创建的歌单

- 标题行左侧“创建的歌单”，右侧“查看全部 + Chevron”；二者垂直居中，触控区至少 `48dp`。
- 列表使用单一低对比 Surface 容器；标准字体下歌单行固定为 `63dp` 密度，封面为 `52dp` 圆角方图。歌单标题按设计画布使用页面专属 `13sp / 18sp` Regular，数量使用 `bodySmall`（`12sp / 18sp`）；大字体状态仍按系统倍率增长，不缩小或裁切。尾部 Chevron 与更多操作分别有明确语义和至少 `48dp` 触控区。
- 当前稿显示三行；更多内容由页面自然滚动，不按画布高度拉伸或压缩行高。
- 无公开歌单时保留区标题，以明确空态替代空白大卡片。

## 主题与图片

- Light 使用现有蓝色主题和柔和 Primary Container；Dark/AMOLED 必须通过语义色生成，不反转确认稿位图。
- 头像和歌单图使用真实位图资源或后续真实 URL，`ContentScale.Crop`；禁止用 Emoji、文本符号、手绘 SVG 或空白占位框模拟可见资产。
- 图片内容可以与确认稿示意不同，但槽位尺寸、主体占比、裁切、圆角、色调密度和留白必须匹配。

## 状态与适配

- Loading、Error、Offline 保留标准 Toolbar；正文状态居中于剩余可用区域，不改变 App 壳层。
- Empty 只表示公开创建歌单为空，资料 Hero 与听歌概览仍保留。
- `fontScale >= 1.3` 时 Hero 信息纵向重排，统计与概览依据实际测量换行；不依赖设备尺寸分档决定业务内容。
- `1.5×` 和 `2.0×` 下所有核心文字与操作都可通过单一纵向滚动到达，且无水平滚动和裁切。
- TalkBack 顺序固定为：返回 → 标题 → 分享 → 更多 → 头像/资料 → 关系统计 → 编辑 → 听歌概览 → 创建歌单标题/查看全部 → 各歌单行。

## 设计符合度验证

1. 使用 `user-profile.content.light` contract，将确认稿 `0,52,853,1620` crop 与 Compose `390 × 843dp` 正常 Light 状态的 `0,0,1024,1945` render crop 等比归一化；App 级 MiniPlayer 区域单独标注，不参与 Feature 内容像素差异结论。
2. 生成并排、50% 叠加和放大差异图，至少核对 Toolbar、Hero、头像、三项统计、编辑按钮、概览卡、歌单标题、首行与第三行锚点。
3.  visible mismatch 必须回到同视口修正并重新比较；单独截图通过不能替代设计符合度。
4. 允许的 P3 差异仅限平台字体栅格、Material 图标笔画和已登记的原创图片内容；组件边界、圆角、间距、行高和信息层级不在豁免范围。
