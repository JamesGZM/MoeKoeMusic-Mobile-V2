# 首页设计复刻与屏幕适配契约

状态：Accepted。确认日期：2026-08-07。适用范围：首页正常态及其加载、空、失败、缓存刷新与部分结果状态。

本文把已确认的 [`01-home-material3-v2.png`](mockups/01-home-material3-v2.png) 转换为可执行的 Android 布局契约。它只约束视觉复刻和屏幕适配，不扩充首页协议、账号依赖、播放架构或目的地。

## 权威顺序与基准语境

1. `01-home-material3-v2.png` 决定首页结构、坐标、比例、间距、圆角、层级和图片裁切。
2. 本文决定设计坐标如何映射到 Compose 页面和应用壳。
3. [`DESIGN_SYSTEM.md`](../DESIGN_SYSTEM.md) 决定颜色语义、字体可访问性、交互状态和最小触控区。
4. 领域模型、字符串资源和协议审计决定正式文案与真实数据；设计图中的歌曲、品质、MV、头像和歌单副标题只是视觉示例。

基准画布为 `852 × 1846` 设计单位，简体中文、Light、系统字体倍率 `1.0×`、竖屏。目标逻辑宽度为 `390dp`，等比高度约为 `844.93dp`。

## 唯一尺寸映射

设设计画布宽度 `Dw = 852`，当前 Compact 页面容器宽度为 `W`：

```text
s = W / Dw
runtimeX = designX × s
runtimeY = designY × s
runtimeSize = designSize × s
```

- 同一页面所有视觉尺寸只使用 `s`，禁止横纵分别缩放或按设备型号分支。
- `W` 来自 Composable 约束，不来自物理像素。页面专属设计单位必须集中换算，不散落为经验 `dp`。
- 所有可交互语义区域至少为 `48 × 48dp`；扩大命中区域不得改变确认稿中的可见图形尺寸。
- Medium/Expanded（`W ≥ 600dp`）没有确认稿时使用最大 `480dp` 的居中单列，不发明双栏或拉满画布。

## 页面区域与所有权

确认稿从上到下由以下固定层级组成：

| 区域 | 固定视觉 | 允许变化 |
| --- | --- | --- |
| 顶部工具区 | 同一行品牌、圆角搜索框、圆形账号入口 | 搜索正式文案；账号图像可使用中性回退 |
| Radio Hero | 左侧音符、三行文案、Filled 主按钮、轮播指示；右侧原创拼贴 | 后续真实 Radio 数据与动作；未接入前保持视觉但不伪造服务结果 |
| 快捷入口 | 单个连续 Surface、三等分入口、图标底板、两条分隔线 | 排行榜属于发现页；未有目的地的入口不新增假路由 |
| 每日推荐 | 蓝色标题标记、右侧更多、四首紧凑歌曲行、封面、标题/艺人、尾部能力区 | 正式歌曲字段、缺图回退；没有真实品质/MV 字段时不展示假徽标 |
| 推荐歌单 | 蓝色标题标记、右侧更多、四列等宽封面与两行文本 | 正式歌单字段；无副标题字段时使用可验证的真实辅助信息或省略 |
| 应用壳 | 连续 MiniPlayer 与三栏底部导航 | 由 `:app` / `:core:designsystem` 所有，首页不得复制 |

首页 Compose 只拥有 MiniPlayer 上方的内容区域。MiniPlayer 和 NavigationBar 固定在 `Scaffold.bottomBar`，不得进入首页滚动列表；首页截图基线与应用壳连续关系必须分别用 feature 截图和 app 集成截图证明。

标准 `390dp`、`1.0×` 状态下，每日推荐使用 `48dp` 紧凑行与 `48dp` 封面；封面来自确认稿中约 `105 × 105` 设计单位按页面唯一系数映射，行间节奏由分隔线和列表编排承担，不能再用历史实现的 `36dp` 封面反写规格。Section Header 视觉高度从 `32dp` 起，推荐区结束后保留 `12dp` 分组留白再进入推荐歌单；四列歌单封面高度为 `88dp`。这些尺寸只约束标准态视觉槽位，点击语义仍不得小于 `48dp`，大字体继续按内容自然增高。

## 滚动、Insets 与状态

- 首页是单一纵向内容流，只允许最外层 `LazyColumn` 成为滚动所有者；Hero、快捷入口、歌曲区和歌单区不得嵌套纵向滚动。
- 基准 `390 × 845dp` 应用壳中，确认稿首屏结构和密度必须与画布一致；真实内容或壳层占用导致溢出时允许首页列表滚动，但 MiniPlayer 与 NavigationBar 始终固定。
- 系统状态栏由 `Scaffold` 内容 Insets 处理。首页不得重复添加系统栏 Padding，也不得绘制到应用壳底栏下方。
- 首次加载在相同页面基座中展示骨架；空内容和首次失败使用可重试页面态；缓存刷新、离线和部分结果保留已有内容并显示非阻断反馈。
- Pull-to-refresh 只移动首页内容，不得拖动或重建应用壳。刷新完成后保留当前有效内容和滚动结构。

## 字体、图片与数据边界

- `1.0×` 使用确认稿字号、字重、行高和单行密度。`1.5×`、`2.0×` 允许文本换行、行高增加和列表滚动，不得缩小系统字号或裁切关键操作。
- Hero 和歌单图使用适配槽位比例的项目位图资源或真实网络封面，必须以 `ContentScale.Crop` 保持比例；禁止空白方块、emoji、字符画或整页截图切片。
- 图片失败时使用统一的中性音乐封面回退。设计稿中的示例账号、歌曲、HQ/MV 和播放数据不得写入运行时领域模型。
- 所有正式可见文案进入 `feature/home` 字符串资源。截图 fixture 可使用虚构数据，但不得反向扩充协议。

## 设计符合度与验收

1. 先以 `390 × 845dp`、Light、`1.0×` 捕获页面和应用壳截图，并归一化到 `852 × 1846` 与确认稿并排、叠加检查。
2. 固定锚点至少覆盖：顶部三节点、Hero 外框与主按钮、快捷入口三槽、两个 Section Header、第一首歌曲封面与尾部操作、四列歌单、MiniPlayer 和 NavigationBar 上边界。
3. 固定区域边界或中心偏差不得超过 `2` 个设计单位，相邻区域累计纵向漂移不得超过 `3` 个设计单位；真实字体栅格和动态图片只可作为遮罩差异。
4. 设计符合度通过后才更新 Compose 回归基线。必须覆盖 Light、Dark、AMOLED、加载、空、首次失败、缓存刷新失败、`1.5×` 和 `2.0×`。
5. 行为验证至少覆盖搜索入口、歌曲播放事件、下拉刷新、滚动可达推荐歌单，以及应用壳下 MiniPlayer/NavigationBar 的固定关系。
