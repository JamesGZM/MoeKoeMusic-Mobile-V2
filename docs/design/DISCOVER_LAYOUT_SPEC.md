# 发现页设计复刻与屏幕适配契约

状态：Accepted。确认日期：2026-08-08。适用范围：发现页精选、歌单、新歌、新碟、排行五个分类入口及其页面状态。

本文把已确认的 [`02-discover-v2.png`](mockups/02-discover-v2.png) 转换为可执行的 Android UI 契约。首个切片只交付可验证的页面视觉与交互状态，不以排行榜、歌单或播放业务尚未接入为由删减确认稿，也不伪造远端结果或新增占位目的地。

## 权威顺序与基准语境

1. `02-discover-v2.png` 决定发现页结构、坐标、比例、间距、圆角、层级和图片裁切。
2. 本文决定设计坐标如何映射到 Compose 页面与应用壳。
3. [`DESIGN_SYSTEM.md`](../DESIGN_SYSTEM.md) 决定颜色语义、字体可访问性、交互状态和最小触控区。
4. 业务接口、领域模型与正式字符串决定后续真实内容；设计图中的歌曲、榜单、歌单和正在播放信息先作为截图 fixture，不反向扩充协议。

基准画布为 `853 × 1844` 设计单位，简体中文、Light、系统字体倍率 `1.0×`、竖屏。目标逻辑宽度为 `390dp`，等比高度约为 `843dp`。

## 唯一尺寸映射

设设计画布宽度 `Dw = 853`，当前 Compact 页面容器宽度为 `W`：

```text
s = W / Dw
runtimeX = designX × s
runtimeY = designY × s
runtimeSize = designSize × s
```

- 同一页面所有可见尺寸只使用 `s`，禁止横纵分别缩放、按设备型号分支或用页面截图充当背景。
- `W` 来自 Composable 约束。Medium/Expanded（`W ≥ 600dp`）没有确认稿时使用最大 `480dp` 的居中单列。
- 所有交互语义区域至少为 `48 × 48dp`；扩大命中区域不得改变确认稿中的图标、胶囊或文字尺寸。

## 页面区域与所有权

| 区域 | 固定视觉 | 首个 UI 切片行为 |
| --- | --- | --- |
| 顶部分段导航 | 五个等宽文字 Tab、当前项主色与底部短指示条、下方分隔线 | Tab 可切换选中态；未定义内容页时继续展示同一预览基座，不新增假路由 |
| 本周新声 Hero | 大幅圆角原创图片、左侧渐变、标题、副标题与 Filled 主按钮 | 按钮提供明确语义；播放服务未接入前不伪造播放结果 |
| 热门排行榜 | 标题与更多、三列榜单封面、角标、榜名、两行歌曲、播放全部 | 三张榜单按确认稿完整展示；入口可为视觉态 |
| 分类歌单 | 标题与更多、横向类型胶囊、三列等宽封面 | 类型胶囊可切换选中态；首屏只需保证封面与下方内容可继续滚动到达 |
| 应用壳 | 连续 MiniPlayer 与三栏底部导航 | 由 `:app` / `:core:designsystem` 所有，发现页不得复制 |

发现页只拥有 MiniPlayer 上方的内容区域。MiniPlayer 和 NavigationBar 固定在 `Scaffold.bottomBar`；feature 截图验证页面内容，app 真机测试验证与壳层的连续关系。

标准 `390dp`、`1.0×` 状态下，五段 Tab 使用 `68dp` 槽位，文字基线相对几何中心下移 `8dp` 并保持指示条贴底；Hero 高度 `215dp`，文字组在中心基准上向下校准 `12dp`。分类胶囊视觉高度 `28dp`，使用紧凑 `labelMedium` 字级；选中与未选中胶囊分别用 `11dp`、`14dp` 水平内容边距，使短中文标签与确认稿宽度一致。胶囊的可见高度不得被扩大成按钮底板，点击命中由 Compose 的最小触控扩展处理。

## 滚动、字体与图片

- 页面只有一个纵向滚动所有者；顶部分段导航随内容滚动，不另加重复 Toolbar 标题。
- 标准首屏保持设计稿密度。内容超出可用高度时自然纵向滚动，MiniPlayer 与 NavigationBar 不参与滚动。
- `1.0×` 匹配确认稿字号、字重与单行密度；`1.5×`、`2.0×` 可增加卡片高度、换行和滚动，但不得缩小系统字号、裁切关键按钮或让 Tab 不可达。
- Hero、榜单和歌单图片使用与槽位比例匹配的项目位图或真实封面，并以 `ContentScale.Crop` 裁切；禁止 emoji、字符画、空白占位框、手绘 SVG 或截图切片。
- 所有正式可见文案进入 `feature/discover` 字符串资源；截图 fixture 可使用虚构内容，但不得进入运行时领域模型或持久化层。

## 页面状态与验收

- 首个 UI 切片至少覆盖 Light、Dark、AMOLED、加载、空、错误、`1.5×` 和 `2.0×`；加载、空和错误保留顶部分段导航与页面结构锚点。
- 设计符合度先以同一视口捕获实现，再把确认稿与实现归一化并排、叠加检查；不能以更新后的截图基线替代设计对照。
- 固定锚点至少覆盖：五个 Tab 与指示条、Hero 外框和按钮、排行榜标题与三列封面、榜单播放入口、分类标题与胶囊、三列歌单，以及 MiniPlayer 上边界。
- 固定区域边界或中心偏差不得超过 `2` 个设计单位，相邻区域累计纵向漂移不得超过 `3` 个设计单位；真实字体栅格和原创图片内容只可作为遮罩差异。
- 行为验证至少覆盖 Tab 切换、分类胶囊切换、纵向滚动到分类内容，以及应用壳下 MiniPlayer/NavigationBar 固定。
