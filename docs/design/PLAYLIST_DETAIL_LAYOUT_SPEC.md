# 歌单详情页设计复刻与屏幕适配契约

状态：Accepted。确认日期：2026-08-08。适用范围：歌单详情正常、加载、空、错误、离线和大字体状态。

本文把已确认的 [`05-playlist-detail.png`](mockups/05-playlist-detail.png) 转换为可执行的 Android UI 契约。首个切片先交付页面视觉、导航和事件端口，不等待歌单业务接口，也不以设计示例数据冒充真实结果。

## 权威顺序与基准语境

1. `05-playlist-detail.png` 决定页面信息层级、坐标、尺寸比例、间距、圆角、封面裁切和首屏密度。
2. [`../DESIGN_SYSTEM.md`](../DESIGN_SYSTEM.md)、`10-user-profile.png`、`15-toolbar-navigation.png` 与 `17-music-content-components.png` 决定主题语义、标准 Toolbar、最小触控区和音乐组件行为。
3. `18-mobile-states-overlays.png` 决定加载、空、持续错误和离线状态语言。
4. 字符串资源、后续领域模型和协议审计决定正式文案与真实数据；设计稿的账号、VIP、歌曲、HQ/MV、时长和封面只用于视觉 fixture。

基准语境为 `853 × 1844px`、简体中文、Light、`fontScale=1.0`。设计中应用壳 MiniPlayer 顶边约为 `y=1672`；Feature 页面只拥有其上方 `853 × 1672` 的区域，MiniPlayer 与系统导航栏继续由 `:app` 固定承载。

## 唯一尺寸映射

- Compact 容器令 `s = min(availableWidth / 853, 1)`；页面设计坐标统一按 `s` 转换为 `Dp`，高度不参与第二次缩放。
- 目标手机宽约 `390dp`，对应 `s ≈ 0.457`；`853 × 1672` 页面区域约映射为 `390 × 764dp`。
- Medium/Expanded 没有独立设计，页面最大宽度 `480dp` 并居中；不得擅自改成双 Pane、横向 Hero 或稀释纵向间距。
- 字体使用 `sp`；`1.0×` 匹配确认稿，触控区至少 `48dp`。`1.3×` 以上允许资料区、操作区和歌曲行增高或换行，但不隐藏主操作。

## 结构与尺寸

| 区域 | 确认结构 | 实现约束 |
| --- | --- | --- |
| Toolbar | 返回、页面中心标题、搜索、更多 | 使用标准 `MoeToolbar`；约 `64dp`，固定在页面顶部，不进入内容滚动 |
| 歌单资料 | 左侧大方形封面；右侧名称、创建者/VIP、数量/时长与两行简介 | 基准宽度保持左右结构；大字体或窄宽允许改为封面在上、资料在下，不裁切文案 |
| 主操作 | 播放全部、随机播放、收藏、下载、更多 | 可见外观按确认稿；前两项为文字按钮，后三项为圆形图标操作；每项触控区不小于 `48dp` |
| 列表标题 | “歌曲”与右侧默认排序 | 固定信息层级；排序入口只发出事件，不在 UI 层伪造排序结果 |
| 歌曲行 | 序号、方形封面、标题/艺人、HQ/MV、时长、更多 | 连续列表，不把普通行卡片化；当前项使用蓝色序号标记和低强调选中容器，不只依赖颜色 |
| 应用壳 | MiniPlayer | 不进入 Feature；详情是子页面，因此隐藏一级 NavigationBar，但保留已有 MiniPlayer |

## 滚动、Insets 与重排

- Toolbar 固定；资料、操作区、列表标题与歌曲列表共同属于一个 `LazyColumn`，它是唯一纵向滚动所有者。
- 正常内容是固有滚动页。初始位置必须为顶部，返回恢复由 Navigation Compose 保存；空、错误和加载状态不得产生可拖动空白。
- Feature 接收 Scaffold 已扣除应用壳后的约束，不再自行添加 MiniPlayer 或底部导航 Padding；顶部系统栏由标准 Toolbar/外层 Scaffold 处理。
- 横屏、短高度和分屏继续使用同一个滚动所有者；大字体不得嵌套纵向滚动。列表行只在文字真实溢出时增高。
- IME 在只读首个切片不适用。后续若搜索进入输入模式，必须另立状态契约。

## 图片、图标与状态

- 封面使用真实 URL 或与槽位比例匹配的项目位图，`ContentScale.Crop`；不得切设计稿、使用空白方块、emoji、字符画或手绘 SVG。
- 图标优先固定版本 Material Icons；返回使用 Design System 已确认导航图标。原图笔画差异只允许作为记录的 P3 差异。
- 正常运行数据缺图时使用 MoeKoe 音乐封面占位语义；截图 fixture 必须使用项目内真实位图资产验证裁切。
- Loading、Empty、Error、Offline 使用公共页面状态组件；有旧内容的刷新后续只能弱提示，不能清空页面或退回首次 Loading。

## 设计符合度与回归

1. 从 `05-playlist-detail.png` 裁去 `y=1672` 以下的应用壳区域，按实现截图归一化；将确认稿和 Compose 正常 Light 状态同画布并排、叠加与差异检查。
2. 固定锚点至少覆盖 Toolbar 四节点、主封面、标题/创建者/统计/简介、五项操作、歌曲标题/排序、首行与当前行。
3. 截图回归覆盖 Light、Dark、AMOLED、Loading、Empty、Error、`1.5×` 与 `2.0×`；更新基线前先证明确认稿符合度。
4. Compose 行为验证覆盖全部可见事件端口、列表滚动、当前项非纯色表达和空/错误零意外滚动。
5. 真机验证从内容页进入、MiniPlayer/一级底栏层级和系统返回；首个纯 UI 切片不验证或伪造网络、收藏、下载、排序及播放业务结果。
