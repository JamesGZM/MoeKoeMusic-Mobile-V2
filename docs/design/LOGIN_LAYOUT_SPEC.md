# 登录页面设计复刻与屏幕适配契约

状态：Accepted。确认日期：2026-08-07。适用范围：登录主页面及 `login-v2` 已确认补充状态。

本文把已确认设计图转换为可执行、可测试的 Android 布局契约。它不重新设计登录页面，也不允许实现者按设备分辨率或个人经验改写组件尺寸。

## 目标与非目标

目标：

- 在基准条件下对已确认设计图做一比一视觉复刻。
- 在其他窗口中保持整套页面的相对比例、锚点、层级和裁切关系。
- 明确系统栏、IME、大字体、触控目标与宽屏等平台约束下唯一允许的适配方式。
- 用设计图与运行截图的直接对比证明符合度，而不是只证明实现自身没有变化。

非目标：

- 不修改验证码、密码、扫码、风控或会话的业务协议。
- 不新增平板双栏、横屏专稿或新的登录内容。
- 不把位图直接作为整页 UI；文字、输入、按钮和语义仍由 Compose 原生实现。
- 不以某台手机的物理分辨率、型号或密度作为分支条件。

## 权威顺序

发生冲突时按以下顺序处理：

1. 已确认页面设计图决定页面几何：结构、坐标、尺寸比例、间距、圆角、层级、Hero 裁切和视觉密度。
2. 本文决定设计坐标如何映射到当前 Android 可用窗口。
3. [`DESIGN_SYSTEM.md`](../DESIGN_SYSTEM.md) 决定颜色语义、交互状态、最小触控区、字体可访问性和共享组件行为。
4. 字符串资源、领域模型和协议审计决定正式文案与真实数据。
5. HTML 原型、历史截图和现有 Compose 实现均不得反向覆盖上述基准。

“Design System Token”不是绕过已确认页面几何的理由。页面专属尺寸必须从设计图测量并登记；共享组件的语义和平台下限仍由 Design System 约束。

## 原型使用决策

登录主状态和 `login-v2` 补充状态已经确认，页面结构、尺寸和状态关系足以直接实现，因此本轮不先制作新原型。后续按以下规则判断：

| 情况 | 处理 |
| --- | --- |
| 设计图已确认，布局和交互无歧义 | 直接完成页面适配契约、Compose 实现和设计符合度测试 |
| 缺少页面或状态设计 | 先补静态设计图并确认，不制作原型、不编码布局 |
| 设计已确认，但复杂手势、转场、滚动吸附或响应式重排仍有明确待定问题 | 只为该问题制作最小原型，验证完成即停止扩展 |
| 倒计时、轮询、请求取消、提交锁定等业务状态 | 使用 ViewModel/状态机和自动测试验证，不为此复制一套视觉原型 |

原型没有页面视觉决定权。它不能改变确认稿坐标、组件比例、图标或密度，也不能成为 Compose 截图基线。

## 基准画布与一比一定义

- 权威主状态：[`13-login-phone-immersive.png`](mockups/13-login-phone-immersive.png)。
- 补充状态：[`login-v2`](mockups/candidates/login-v2/README.md) 中的独立确认稿。
- 所有登录确认稿画布均为 `852 × 1846` 设计单位，宽高比约为 `0.46154`。
- 基准语境为：简体中文、浅色主题、系统字体倍率 `1.0×`、无 IME、竖屏。
- “一比一”指运行结果逆向归一化到 `852 × 1846` 后，固定视觉区的边界、中心、间距、比例、圆角和裁切与确认稿重合；不是指把 `852px` 直接当作 Android `852dp`。

登录主稿的目标逻辑宽度继续记为 `390dp`，由此得到等比内容高度约 `844.93dp`，文档中可写作 `390 × 845dp`。旧文档中的 `390 × 844dp` 只表示目标设备级别，不能作为纵向压缩一设计单位的依据。

## 统一尺寸映射

设设计画布宽度 `Dw = 852`，当前登录页面实际可用容器宽度为 `W`，页面视觉缩放系数为：

```text
s = W / Dw
runtimeX = designX × s
runtimeY = designY × s
runtimeSize = designSize × s
```

强制规则：

- 同一页面内的坐标、间距、视觉组件宽高、图标、圆角、描边和普通态字号使用同一个 `s`；禁止为不同组件选择不同缩放系数。
- 只按宽度求 `s`，禁止根据高度再次压缩，禁止横纵分别拉伸。
- `W` 来自当前 Composable 的约束和窗口边界，不来自物理屏幕像素、设备型号或固定分辨率表。
- 原始设计像素只存在于页面规格和测量数据中；Compose 实现应集中转换为 `Dp`/`Sp`，不得散落原始 `px` 常量。
- 窗口高度大于等比画布高度时，保留设计锚点并把多余高度留给页面背景或外部居中容器，不能把纵向间距逐项拉大。
- 窗口高度小于等比画布高度时，保持宽度比例并由单一纵向滚动容器保证可达，不能整体纵向压扁。

示例：用户当前 ELE-AL00 的截图分辨率为 `1080 × 2340`，与 `852 × 1846` 的宽高比完全一致；在不计截图采集差异时，统一比例 `1080 / 852 = 2340 / 1846`，因此不应再基于这台设备单独修改卡片或字段尺寸。

## 页面坐标与区域所有权

登录页面划分为以下区域，均使用同一设计坐标系：

| 区域 | 固定内容 | 允许变化 |
| --- | --- | --- |
| Hero | 插画裁切、品牌标题、欢迎文案、返回按钮视觉锚点 | 系统安全区避让；深色主题允许按 Design System 加对比遮罩 |
| 登录 Surface | 外框、顶部位置、宽度、圆角、与 Hero 的覆盖关系 | 短高度时随整页滚动，不单独改变比例 |
| 模式分段 | 外框、三槽等分关系、选中背景、文字中心 | 仅选中状态与正式文案变化 |
| 表单内容 | 标题、输入、按钮、协议和安全页脚的设计锚点 | 按对应状态稿替换已登记内容；动态错误只占允许区域 |
| 覆盖层 | 完整底图、遮罩、Dialog 中心与尺寸 | Dialog 内容状态变化；底层页面不得移动 |

`13-login-phone-immersive.png` 的固定画布应在实现前形成测量清单，至少记录 Hero 裁切框、返回按钮中心、品牌块、Surface 外框、分段控件、标题、各输入框、主按钮、协议区、分隔线和安全页脚的设计坐标。测量值直接来自原图，不允许从现有 Compose 反推。设计资产没有变更时，测量清单不得随实现方便而更新。

当前主稿的登录专属锚点为：返回按钮可见圆形左边缘与登录 Surface 左边缘共同对齐 `x = 28`，圆心为 `(76, 143)`；箭头图形复用 Design System 的圆端 `MoeNavigateBackIcon`，登录页只登记 `27 × 40` 的图形视口和 `96` 的圆形底板，仍保持独立 `48dp` 最小触控区。登录 Surface 顶部约 `y = 565..566`、底部几何锚点约 `y = 1820`、设计画布底部间距 `26`；安全页脚两条装饰线分别为 `x = 197..385` 和 `x = 463..651`、各 `189` 长、中心线约 `y = 1435`。装饰线是固定端点，不得使用 `weight` 自动吃满剩余宽度。

登录 Surface 在浅色主题使用白色表面和冷蓝柔光，不使用 Material 默认黑灰 elevation：页面背景基准接近 `#F9FBFE`，Surface 接近 `#FEFEFE`。API 29 复核证明系统彩色 elevation 只能形成贴边色带，不能稳定复刻设计稿的扩散，因此 Card 使用兼容 API 26 的确定性多层主蓝光晕：最大扩张 `16` 个设计单位，从外到内逐设计单位叠加约 `0.25%..0.85%` 透明度，并以主蓝色约 `8%` 的一设计单位边缘取代灰色描边。目标是在距边缘约 `4 / 10` 设计单位处分别接近 `RGB(237,242,254) / RGB(244,248,253)`。阴影参数必须通过边缘像素衰减复核，不能回退成肉眼明显的深灰底边或只剩一条蓝色描边。

模式分段控件固定为 `90` 高、`30` 外圆角、`8` 内边距与槽间距、`22` 选中块圆角；浅色容器为中性冷灰 `#F6F6F8`。标签使用 `28 / 38` 字号与行高，三个图标使用登录专属盾牌、锁和扫码 VectorDrawable，不使用形态不同的 Material 近似图标。选中块作为跨模式稳定的同一个节点，在三等分槽位之间以 `260ms` FastOutSlowIn 位移动画切换，图标和文字颜色以 `180ms` 过渡；切换内容不得重建 selector 或让动画从终点重新开始。

模式分段的按压态不显示额外涟漪、点击阴影或 elevation 跳变；选中块自身的常驻 Surface、描边和层次仍按确认稿保留。验证码、密码和扫码是同一登录目的地内的并列分支，切换模式只改变当前可见内容，不能重建整份登录状态：各分支的输入草稿、密码可见性、多账号上下文和内联反馈分别保留且不得串到其他分支。短信倒计时和二维码会话绑定登录 ViewModel 生命周期，切到其他模式后继续按真实一秒节拍递减，二维码轮询继续使用原 session；切回扫码不得隐式重新生成二维码，只有首次进入、明确刷新或终态重试才允许创建新 session。状态任务在登录目的地真正销毁时随 `viewModelScope` 取消。

`login-v2` 各状态继续遵守其“固定基座 / 允许变化区域”矩阵；同一状态以对应独立 PNG 为完整视觉期望，不能只对主稿做宽松风格参考。

Hero 原始插画必须保持宽高比，并绘制在 `y = 0..627` 的固定 Hero 视口内；当前 1672×941 资产使用 `ContentScale.Crop` 居中裁切左右边缘。登录 Surface 从 `y = 566` 开始绘制在 Hero 之上，形成 `61` 个设计单位的真实覆盖，圆角外侧仍能看到插画。Hero 底部另有一层绘制在插画之上的 Surface 色纵向渐变：`72%` 前保持透明，`84% / 92% / 100%` 位置的 Surface 色透明度依次约为 `14% / 62% / 94%`，使插画先融入页面白色背景，再由悬浮 Surface 覆盖；该渐变不是缩短图片或在 Card 前填充白块。不得在 `cardTop` 提前终止图片、使用 `FillBounds` 纵向拉伸人物，或用纯色填补到 Card。裁切、对齐和渐变层级属于设计测量值，资产或确认稿变化时才允许调整。

## 系统边界、IME 与滚动

- 页面默认 edge-to-edge，Hero 可绘制到系统栏后方；真实状态栏图标由系统绘制，设计图中的示意系统图标不属于 App 资产。
- 返回按钮的视觉中心保持设计锚点；若锚点落入 cutout 或不可安全点击区域，只允许增加安全区位移，且必须记录为平台遮罩差异。
- 底部导航栏/手势区不能遮挡协议、页脚或提交后的反馈；安全区通过外层容器处理，不通过缩小所有组件解决。
- 登录目的地不创建、不显示也不测量应用壳 MiniPlayer 或 BottomBar。完整沉浸式画布绘制到系统栏后方，但 Surface 的运行时底部间距必须为 `26 × s + navigationBars.bottom`，只压缩页脚之后的弹性空白，使卡片底边始终位于三键/手势导航安全区上方；短窗口仍由登录页唯一外层滚动处理。
- 登录页不是固有滚动页面。所有已确认状态在约 `390 × 845dp`、`fontScale = 1.0`、无 IME 的基准条件下必须完整显示，纵向滚动范围严格为 `0`；用户上滑、下滑不能移动 Hero、Surface、表单或产生可见空白。
- 禁止为兼容未来小屏而无条件给基准画布添加 `verticalScroll`。滚动只能在可观测的内容高度大于实际可用高度、IME 遮挡、系统大字体导致重排，或短高度/分屏窗口不能完整承载设计时启用。
- IME 出现时不重新计算宽度缩放系数。条件滚动使用唯一外层滚动所有者，并把当前输入、内联错误和主操作带入可视范围；IME 关闭且内容重新完整容纳后，滚动位置复位为 `0`。
- 小高度、分屏和横屏没有独立确认稿时，不创造新布局；保持同一竖向设计结构并使用条件滚动。后续若要改变为横向专用结构，必须先补设计图。
- Hero 与登录 Surface 的覆盖关系属于设计坐标，而不是额外内容高度。使用 `offset` 或绘制变换只能移动视觉位置，通常不会减少父布局测量占位；若把这种节点放进滚动 Column，必须显式消除其不可见占位，保证最终测量边界等于设计画布。优先在固定尺寸 `Box`/自定义布局中按设计坐标放置重叠区域，再只在条件成立时让完整画布参与滚动。
- 系统 overscroll 效果不得掩盖错误：基准场景既不能有真实位移，也不应因可滚动容器产生拉伸/回弹提示。条件滚动启用时是否保留 overscroll 必须与产品体验一致且不改变内容坐标。
- 实现中的最小页面内容高度必须来自 `1846 × s` 设计画布，Card 最小高度来自 `canvasHeight - cardTop - cardBottomMargin`；禁止用当前视口 `maxHeight` 计算 Card 高度。系统导航栏、分屏或短窗只缩短视口，并由真实溢出产生滚动，不能压缩设计结构。

## 状态文案、图标与反馈槽

- 手机号发送成功、手机号校验错误、验证码校验错误和服务错误使用同一内联反馈组件、同一字号/行高和固定单行占位；显示/隐藏不会改变主按钮锚点。
- 密码错误沿用同一反馈规则；`19c-password-rejected.png` 的错误文案和密码可见性图标是独立验收项，图标颜色、线宽和语义状态均须核对。
- QR 生成、等待、已扫码、过期、失败必须分别对应 `20a` 至 `20e`。`20c` 固定为“已扫码，请在手机上确认 / 请在手机上完成登录确认”；等待与已扫码状态的倒计时仅时间段使用主蓝色。
- “打开酷狗音乐”必须完整显示；酷狗标识、二维码中心标识、返回箭头不得用未经确认的近似字符或粗细不同的通用图标替代。
- 每一种确认状态必须有 Compose Preview；Preview、真机截图和设计稿叠加使用同一正式字符串与正式资源，禁止用过期截图证明新代码。
- 日常几何和视觉调整优先使用 `390 × 845dp` Compose Preview；另提供显式底部安全区 Preview（当前以 `56dp` 模拟三键导航）。真机只用于验证真实 Insets、系统栏、触控和最终设备差异，不作为每轮布局微调的唯一反馈工具。

## 字体与无障碍例外

- 在 `fontScale = 1.0` 的基准语境中，文字字号、行高、字重和基线必须匹配设计图，不允许以设备分辨率为由单独放大或缩小。
- Compose 文字使用 `sp` 并尊重系统字体倍率。`1.5×`、`2.0×` 时允许组件按内容增高、文本换行和页面滚动；禁止缩小系统字号、裁切关键信息或让操作消失。
- 字体倍率导致的重排是明确的无障碍适配，不作为基准像素不一致；但页面层级、水平顺序和操作优先级必须保留。
- 视觉控件可以按设计缩放，所有可交互语义区域仍不得小于 `48 × 48dp`。扩大点击区不得改变可见图形尺寸和相邻布局。
- 动态文案使用字符串资源。设计稿示例文本与正式文案长度不同，必须优先保证完整语义，并在状态允许区域内换行或增高。

## 不同宽度的适配策略

- Compact（窗口宽度 `< 600dp`）：以当前容器宽度完整承载设计画布，严格执行统一宽度缩放。
- Medium/Expanded（窗口宽度 `≥ 600dp`）：没有已确认宽屏登录稿时，不把竖屏画布拉满全窗，也不发明双栏。使用居中的单列登录画布，画布最大宽度为 `480dp`，周围延续 Hero/页面背景；画布内部仍按同一比例映射。
- 折叠屏铰链或显示特征不得穿过登录画布；必要时把完整单列画布放入较合适的安全窗格，不拆分表单。
- 宽屏规则属于从现有竖屏设计派生的保守适配；未来确认专用宽屏稿后，由新设计替换，不能在代码中自行扩展。

## 视觉符合度测试

设计符合度与截图回归是两套不同测试：

1. 设计符合度：确认稿是期望值。运行截图按实际画布边界逆向归一化到 `852 × 1846`，再与对应 PNG 叠加比较。
2. 截图回归：只有设计符合度通过后，Compose 截图才能成为防止已批准实现意外变化的回归基线。

设计符合度报告至少包含：

- 目标设计文件、状态名、主题、语言和字体倍率。
- 物理截图尺寸、密度、逻辑窗口尺寸、页面实际约束、状态栏/导航栏/cutout/IME Insets。
- 统一缩放系数和逆向归一化方式。
- 固定锚点的实际/期望坐标差，以及半透明叠加图或差异图。
- 被遮罩的真实系统图标、时间、动态账号、二维码和倒计时区域。

在基准语境中，固定区域的边界或中心偏差不得超过 `2` 个设计单位；相邻组件的累计纵向漂移不得超过 `3` 个设计单位；不允许肉眼可见的横向拉伸、独立缩放或错误 Hero 裁切。抗锯齿和字体栅格差异按遮罩后的视觉复核处理，不能借此放宽结构坐标。

更新截图基准前必须先出设计叠加证据。仅执行截图录制命令并让测试变绿，不能证明 UI 符合设计，也不能作为批准更新基准的理由。

## 验收矩阵

显示矩阵与 Android API 矩阵必须分开记录：

| 类型 | 必测条件 |
| --- | --- |
| 设计基准 | `852 × 1846` 归一化、简体中文、Light、`1.0×` |
| 目标手机 | `390 × 845dp` 等比视口、Light/Dark/AMOLED |
| 当前真机 | 记录 `1080 × 2340px`、密度、实际窗口、Insets、导航模式与字体倍率 |
| 紧凑边界 | 至少一个更窄窗口、一个更短/分屏窗口，验证比例与滚动 |
| 字体 | `1.0×`、`1.5×`、`2.0×`，关键操作可达且不裁切 |
| 系统 | 状态栏、手势/三键导航、IME、旋转和进程恢复 |
| 宽屏 | Medium/Expanded 居中单列，不拉伸、不擅自双栏 |

平台 API 继续按 [`TESTING_STRATEGY.md`](../TESTING_STRATEGY.md) 执行；同一 API 版本并不能代表所有窗口尺寸，同一窗口尺寸也不能替代 API 兼容验证。

滚动行为必须有独立自动证据：

- 基准手机号、密码、扫码、风险覆盖层和多账号状态的滚动轴最大值为 `0`，执行上滑/下滑后固定锚点和滚动位置不变。
- 短高度、IME、`1.5×` 和 `2.0×` 字体中，只在内容确实溢出时滚动轴最大值大于 `0`，最后一个关键操作可滚动到可见并点击。
- 从条件滚动恢复到基准条件时位置回到 `0`，不能让页面停留在中间或暴露画布外空白。
- 设计重叠区域的父布局测量高度必须与归一化画布边界一致，不得包含因负 `offset` 遗留的额外滚动距离。
- 模式往返必须验证手机号/验证码、账号选择、用户名/密码、密码可见性和各自反馈不丢失且不串页；短信与二维码倒计时切走后继续递减，扫码返回时 session 不重建。

## 重新落地门禁

登录 UI 只有同时满足以下条件才可标记视觉完成：

1. 页面测量清单来自确认稿，且实现只消费集中式设计尺寸映射。
2. 手机号验证码默认、发送中、倒计时、输入与提交状态先完成设计符合度验证。
3. 密码、扫码、风险和多账号逐状态使用对应确认稿验证，底层固定区域不漂移。
4. 基准、当前真机、紧凑边界、大字体和宽屏派生规则均有证据。
5. 所有确认状态在基准条件下滚动范围为 `0`；条件滚动只在短高度、IME 或大字体真实溢出时启用并可恢复归零。
6. 截图基准只在设计符合度通过后更新。
7. 代码行为测试、无障碍测试和真机自动测试通过；需要用户手动输入验证码、密码或扫码的真实账号场景单独列为未执行项。

在上述条件完成前，历史“登录视觉已完成”结论撤回；既有截图只能视为旧实现的回归记录。
